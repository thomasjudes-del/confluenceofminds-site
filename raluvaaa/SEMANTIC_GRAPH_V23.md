# RALUVAAA V23 - Semantic graph contract

## Core rule

**One root wish = one lineage.** A lineage is the visible history and descendants of one original intention. It is not a person profile and not a thematic cluster.

A human can own several independent lineages. They share a private `owner_id` / `wisher_id` in data, but they are not automatically placed together or visually connected.

## Product semantics

- **CREATE** creates a new independent lineage.
- **PIVOT** changes the direction of the same wish while preserving the earlier path as history.
- **SPLIT** creates real child wishes / sub-intentions inside the same lineage. Children can split recursively.
- **BLOOM** marks a wish or sub-wish accomplished, confirmed only by the wisher. The branch remains as an accomplished trace and may visually patinate over time.
- **LET GO** voluntarily abandons a wish or sub-wish without deleting its trace.
- **ENCOURAGE** injects energy. It creates no topology and cannot imply completion.
- **HELP** is a persistent concrete contribution. Preferred visual metaphor: leaves / buds / partial flowering around the targeted node or branch. HELP is visually an antechamber to Bloom, but it can never automatically declare Bloom.
- **CONNECT / CARRY** creates a relationship between two independent lineages. It is a distinct warp / bridge, not a biological parent-child edge.

## Meaningful nodes

The product distinguishes semantic nodes from rendering control points. Only semantic nodes are interactive and meaningful. Curve-control points must never surface as unexplained nodes, Root IDs, Route IDs or generation labels.

## Selection

Selecting a semantic node should make the selected point unmistakable, softly illuminate the path from origin to that point, and reveal relevant CONNECT / CARRY warps with subtle remote endpoint echoes.

## Simulation rule

The simulated world is generated from coherent wish histories first, then drawn with the locked V03 visual language. It must never paste unrelated wish texts onto arbitrary V03 nodes.

Target population for the semantic test: 100 simulated root wishes plus descendants, pivots, nested splits, blooms, let-go traces, help traces, encouragement history and a small number of explicit cross-lineage warps. Simulation is always identified as SIMULATED when surfaced as data.

## Graphical lock

Visual baseline remains `VISUAL-V03-LOCKED`: palette, organic line language, halos, pan/zoom, minimap and performance envelope. Semantic topology may change because branches now have meaning, but rejected V18-V21 renderer styles must not return.

## Versioning

- Visual: `VISUAL-V03-LOCKED`
- Product: `PRODUCT-V20`
- Semantic population experiment: `SEMANTIC-V23`
